# Карта данных и анализ предметной области

## 1. Описание предметной области

Розничная торговля. Датасет описывает работу кассового узла в сети магазинов, включая данные о товарах, чеках, кассирах и клиентах. Автоматизируются такие процессы как : Сканирование товаров, формирование чека, применение скидок, проведение оплаты, закрытие кассовой смены с подсчетом выручки, оформление возвратов товаров. Пользователями системы являются: кассиры, менеджеры, аналитики и администраторы баз данных. На основе данных решаются какие товары пользуются спросом, в какие часы/дни пик выручки, оценка эффективности работы кассиров.

## 2. Выделение сущностей и атрибутов 

1. **stores (Магазины):**
   * Назначение: Хранение информации о точках продаж.
   * Ключевые атрибуты: `store_id` (PK), `address`, `phone`.
   * Обоснование типов: `SERIAL` для автоинкремента ID. `TEXT` для адреса. `VARCHAR(20)` для телефона.

2. **employees (Сотрудники)**
   * Назначение: Учёт кассиров и менеджеров.
   * Ключевые атрибуты: `employee_id` (PK), `full_name` (NOT NULL, ПДн), `role` (CHECK: cashier/admin/manager), `store_id` (FK).
   * Обоснование типов: `VARCHAR(100)` для ФИО. Ограничение `CHECK` не позволяет создать сотрудника с несуществующей должностью.

3. **products (Товары)**
   * Назначение: Каталог товаров с ценами.
   * Ключевые атрибуты: `product_id` (PK), `sku` (UNIQUE, артикул), `name` (NOT NULL), `price`, `category_id` (FK).
   * Обоснование типов: `NUMERIC(10,2)` выбран для точного хранения денежных сумм без потери копеек.

4. **customers (Клиенты)**
   * Назначение: Программа лояльности.
   * Ключевые атрибуты: `customer_id` (PK), `phone` (UNIQUE, ПДн), `bonus_points` (CHECK >= 0).
   * Обоснование типов: `phone` имеет ограничение `UNIQUE`, чтобы один телефон нельзя было привязать к двум разным аккаунтам.

5. **shifts (Кассовые смены)**
   * Назначение: Учёт рабочего времени кассира и привязка чеков к смене.
   * Ключевые атрибуты: `shift_id` (PK), `store_id` (FK), `employee_id` (FK), `open_time`, `close_time`.
   * Обоснование типов: `TIMESTAMP` для точного времени. Ограничение `CHECK` гарантирует, что время закрытия смены будет позже времени открытия.

6. **receipts (Чеки)**
   * Назначение: Заголовок чека.
   * Ключевые атрибуты: `receipt_id` (PK), `shift_id` (FK), `customer_id` (FK), `created_at`, `total_amount`.
   * Обоснование типов: `BIGSERIAL` используется для ID чека, так как со временем чеков может стать очень много, и обычный `SERIAL` может переполниться.

7. **payments (Оплаты)**
   * Назначение: Разделение оплаты (наличные, карта). Один чек может быть оплачен разными способами.
   * Ключевые атрибуты: `payment_id` (PK), `receipt_id` (FK), `payment_type` (CHECK: cash/card), `amount` (CHECK > 0).
   * Обоснование типов: `BIGSERIAL` для `payment_id`, `VARCHAR(10)` для `payment_type` экономит место на диске,  `CHECK` гарантирует, что кассир не введет ошибочный тип оплаты, `NUMERIC(10,2)` исключает потерю копеек при расчетах.

8. **returns (Возвраты)**
    * Назначение: Учёт возвратов товаров по чеку.
    * Ключевые атрибуты: `return_id` (PK), `receipt_id` (FK), `reason` (причина возврата), `refund_amount`.
    * Обоснование типов:`TEXT` для поля `reason` позволяет хранить причину возврата, `NUMERIC(10,2)` для `refund_amount` строгая типизация денег,  `CHECK > 0` защищает от случайного ввода отрицательной суммы возврата.

### Классификация атрибутов:
* Обязательные: `stores.address`, `employees.full_name`, `categories.name`, `products.sku`, `products.name`, `products.price`, `receipts.total_amount`, `receipt_items.quantity`, `receipt_items.price_at_sale`. Без них система не сможет корректно работать.
* Уникальные: `categories.name`, `products.sku`, `customers.phone`.
* Ссылочные: `employees.store_id`, `products.category_id`, `shifts.store_id`, `shifts.employee_id`, `receipts.shift_id`, `receipts.customer_id`, `receipt_items.receipt_id`, `receipt_items.product_id`, `payments.receipt_id`, `returns.receipt_id`.

## 4. Классификация данных 
- Персональные данные: Номера телефонов клиентов (`customers.phone`), ФИО сотрудников (`employees.full_name`). 
- Коммерческая тайна: Себестоимость и цены товаров (`products.price`), суммы (`receipts.total_amount`). 
- Открытые данные: Адреса магазинов (`stores.address`), названия категорий (`categories.name`), названия товаров (`products.name`).

## 5. Реализация DDL-скрипта
DDL-скрипт, создающий данную структуру с ограничениями (PK, FK, NOT NULL, UNIQUE, CHECK) и B-tree индексами для ускорения поиска (по датам чеков и категориям товаров), реализован в файле `sql/schema.sql`.
